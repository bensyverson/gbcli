# Vendoring SameBoy: commit, flags, feature switches

2026-11-06, scaffold leaf `eeTyfo`. How SameBoy enters the build, and why.

`crates/sameboy-sys/SameBoy/` holds SameBoy's `Core/`, the boot ROM sources from `BootROMs/` (`*.asm`, `*.inc`, `pb12.c`, `SameBoyLogo.png`), `LICENSE` (Expat) and `version.mk`, at **`ea667ad79aa28409f034b1fd6da7304e1844750d`** (2026-11-02, "Merge branch 'master' of github.com:LIJI32/SameBoy"; version 1.0.5). The commit is also in `SameBoy/COMMIT`, which `sameboy_sys::SAMEBOY_COMMIT` reads, so the checkpoint envelope can name its core commit from the one place.

> **Correction, 2026-11-06 (leaf n2WX5r): `Core/` is no longer unmodified.** It carries one observation-only patch of ours, [the layer-identity patch](#gbclis-layer-identity-patch), applied by `scripts/vendor-sameboy.sh`. Everything else is still upstream's.
>
> **Update, 2026-11-09 (leaf si5fnG): a second observation-only patch,** [the mode-blocked-writes patch](#gbclis-mode-blocked-writes-patch), reports the CPU writes the PPU ignores. It adds no saved state, but like any patch it changes the core identity, so states saved by earlier builds are refused ([The core identity](#the-core-identity)).

**Why this commit:** it was the latest `master` when the scaffold was built (a `git clone --depth 1` on 2026-11-06 resolved to it), and it is the commit the backend evaluation read and measured, so every line reference and measured figure in [2026-11-06-backend-evaluation.md](2026-11-06-backend-evaluation.md) applies to the vendored code as is.

**To move it:** `scripts/vendor-sameboy.sh [commit]` replaces the vendored tree, re-applies `crates/sameboy-sys/patches/*.patch`, and rewrites `COMMIT`; then `scripts/build-roms.sh` rebuilds the boot ROMs, and this doc (or a new dated one) records the new commit and why. If the patch's `git apply --check` fails, the new commit moved the code it touches: rebase the patch, don't drop it.

## gbcli's layer-identity patch

`crates/sameboy-sys/patches/layer-identity.patch` (leaf n2WX5r) makes SameBoy record **which layer drew each pixel**: background, window, or an OAM object and its index. SameBoy decides the winner of every pixel at one mixing point and then discards it; the patch writes that decision to an optional side buffer instead of inferring it later. Replaying with rendering disabled or re-rendering from VRAM/OAM would change object fetch (and therefore mode-3 timing) or be wrong under mid-line raster changes, so neither is used.

What it touches:

- **`Core/display.h`** — `GB_fifo_item_t` gains `window` (the BG FIFO: the row was pushed from the window map) and `object` (the OAM FIFO: the OAM index of the object that won the pixel). That grows the item from 4 to 6 bytes; the two FIFOs sit in SameBoy's saved `video` section, so the save state grows by 32 bytes (DMG cpu_instrs: 50,712 → 50,744). A checkpoint written by a build without the patch is therefore not compatible, which the envelope's core-commit field already rules out.

  > **Correction, 2026-11-06 (review, `project/2026-11-06-review-fixes.md`): it did not.** The patch changed no version: `blob::VERSION` (2), SameBoy's `STRUCT_VERSION` (15) and the recorded commit were all unchanged, and the core commit only ever raised a warning anyway. SameBoy's `read_section` accepts the shorter section and shifts every later field, so a pre-patch checkpoint or boot-cache entry loaded silently and diverged within 1–3 frames (run by the reviewer). Leaf `46uWtG` fixed it: pre-patch states are now refused, and so is any state saved under another patch set — see [The core identity](#the-core-identity).

  It also names the tag encoding once: `GBCLI_LAYER_BACKGROUND` (0), `GBCLI_LAYER_WINDOW` (1) and `GBCLI_LAYER_OBJECT` (2, plus the OAM index), an enum next to `GB_fifo_item_t` (leaf XKaz0o). The Rust mirror is `sameboy_sys::GBCLI_LAYER_*`, decoded in one place (`hooks.rs`, `layer()`), and `crates/sameboy-sys/tests/layer_tags.rs` checks it against the C values that `shim/gbcli_layers.c` exports. The first version of the patch also replaced a no-break space in upstream's `bg_priority` comment; that line is upstream's again, so the patch touches only what it needs.
- **`Core/gb.h`** — a `layer_buffer` pointer next to `screen`, inside the **unsaved** section: one tag per pixel, in rows of 160. It is never written to a save state and never read from one; the caller owns the memory.
- **`Core/display.c`** — the two FIFO push functions carry the tags; `layer_store` writes a `GBCLI_LAYER_*` tag at `x + y * 160` when the pointer is non-NULL. It is called at both mixing points: `render_pixel_if_possible` (the per-pixel path) and `render_line` (the batched path), including that function's BG-disabled branch, and the object index is also recorded in `render_line`'s local object buffer. The window flag comes from `gb->wx_triggered` on the BG FIFO push. Nothing reads the buffer, and no pixel, register or state depends on it. Two recovery paths — the mode-3 abort (`display9`) and the PPU/LCD desync fill — write a color without visiting the mixing point; those pixels keep the buffer's background tag, and they only happen when a ROM desynchronizes the PPU.

  **The DMG window pixel-insertion glitch is tagged background** (a ruling, leaf XKaz0o). SameBoy inserts one extra BG-palette color-0 pixel in two cases: when LCDC.5 is off but WX matches the fetcher's position (`display.c`, the `GB_FETCHER_PUSH` case, SameBoy issue 278), and when WX matches again while the window is already active (`insert_bg_pixel`). In both the inserted item is `{0}`, so its tag is background. In the first case that is simply true: the window is disabled and nothing was fetched from its map. In the second the pixel sits inside the window's span, so "window" would be as defensible; it stays background because the pixel comes from no map at all (it is the FIFO's color 0, not a window tile), because tagging it window would need the patch to touch `render_pixel_if_possible`'s static empty item, and because no test ROM here can trigger it to check either answer. A reader who sees one background pixel inside a window run on DMG is looking at this glitch.
- **What the patch costs with no buffer.** With `layer_buffer == NULL` no tag is written, but the patch is not free:

  > **Correction, 2026-11-06 (review, leaf XKaz0o): the "only cost is one predictable branch and one pointer load per drawn pixel" claim was wrong.** The off path also carries the two extra bytes of every `GB_fifo_item_t` (4 → 6 bytes, so the FIFOs' pushes, pops and copies move more data) and the stores of `window` and `object` into them, the `layer` value computed at both mixing points, and one more bitfield store per object pixel in `render_line`'s object buffer (whose entry stays 4 bytes: 12 bits grow to 18). There is still no allocation, no second pass and no change to any pixel. The measured cost is in [Throughput](#throughput-buffer-off-versus-on).
- **Shim** (ours, not part of the patch): `shim/gbcli_shim.c` has `gbcli_set_layer_buffer(gb, buffer)`, which attaches or detaches the buffer, and `gbcli_frame_scrubbed(gb)`, which reports SameBoy's blank, substituted frame after the LCD is turned on (`frame_skip_state == GB_FRAMESKIP_LCD_TURNED_ON`), so no layer map is published for pixels that were never rendered. `shim/gbcli_layers.c` exports the tag values for the test of their Rust mirror. The FFI declarations are in `crates/sameboy-sys/src/lib.rs`.
- **Rust** (`crates/sameboy/src/lib.rs`, `hooks.rs`): `Core::set_pixel_layers(on)` turns capture on, off by default (turning it on again is a no-op that keeps the current map), and `Core::pixel_layers()` returns the last complete frame's map; the tags are copied at vblank into `Hooks::frame`, like the pixels, so the map always describes the frame `last_complete_frame` publishes. `Feature::PixelLayers` is `Yes` on DMG/MGB/CGB with rendering on; `No` on SGB, whose border and mask modes are composited in `sgb.c` after the PPU's mixing point, and `No` with `Rendering::Off`, where `display.c` drops every pixel before the mixing point (`set_pixel_layers(true)` refuses with the remedy: build the core with `Rendering::On`).

  **Only a frame captured whole gets a map** (leaf XKaz0o). A frame already under way when capture is turned on, or when a state is loaded (the buffer holds the old timeline's tags for the rows already drawn), is dropped at its vblank; the next one has a map. "Under way" means some pixel of it was drawn: the LCD is on and the PPU is past line 0's OAM scan and not in vblank, read from STAT and LY in the IO array, which describe how far the PPU has actually run (it draws nothing ahead of that, even while batching). So a checkpoint taken at a frame stop and loaded maps the very next frame. Every vblank, published or not, ends the frame the buffer was collecting: a CGB `GB_VBLANK_TYPE_REPEAT` (the first frame after a quick LCD off/on, where the screen keeps the previous frame) keeps the previous frame's map but no longer carries the "partly captured" mark into the whole frame after it, which used to lose that frame's map too. DMG STOP with the LCD on (`display.c`'s `is_ppu_stopped` black screen) cannot publish a map: while `gb->stopped` on DMG, `GB_display_run` returns before the PPU state machine and emits only `GB_VBLANK_TYPE_ARTIFICIAL` vblanks, which get no map, and gbcli's run loop stops with `StopReason::Stopped` rather than run a STOP no key can end.

The patch is separable and small enough to offer upstream; the FIFO growth is the only part that changes SameBoy's state layout.

### Throughput: buffer off versus on

Measured 2026-11-06 on an Apple M1 (8 CPUs, Apple clang 21) shared with other agents' builds (load average 23–42 during the runs). The machine's same-binary run-to-run spread was about ±2%, so the off cost is reported as the median of paired runs that started simultaneously.

**Off, against an unpatched SameBoy.** Both binaries are `scripts/bench/sameboy-throughput/sb_bench.c` compiled with `build.rs`'s flags, one against a pristine clone of `ea667ad` and one against `crates/sameboy-sys/SameBoy`; a copy of the harness whose `now()` reads `CLOCK_PROCESS_CPUTIME_ID` gives CPU seconds:

```sh
# For each tree: then run sb_bench against cpu_instrs for 7,200 frames, rendering on.
cd <tree>/Core
cc -O3 -std=gnu11 -D_GNU_SOURCE -DGB_INTERNAL -DNDEBUG -DGB_VERSION='"1.0.5"' \
   -DGB_COPYRIGHT_YEAR='"2026"' -DGB_DISABLE_DEBUGGER -DGB_DISABLE_REWIND \
   -DGB_DISABLE_CHEAT_SEARCH -I<tree> -o /tmp/sb_bench <sb_bench.c> \
   $(print -l *.c | grep -vE '^(debugger|sm83_disassembler|symbol_hash|rewind|cheat_search)\.c$') -lm
```

Eight simultaneously-started, interleaved pairs at 7,200 frames each: **median +0.44%**, range −0.94% to +1.85%. That is at the measurement floor; structurally the off path is one well-predicted branch per pixel, and no pixel or state value changes.

> **Correction, 2026-11-06 (leaf XKaz0o): re-measured with a committed harness; the off cost is about +1%, and it is more than one branch.** The CPU-clock copy of `sb_bench.c` behind the +0.44% was never committed; `sb_bench.c` now has that clock behind `-DSB_BENCH_CPU_TIME`, and `scripts/bench/layer-patch-cost/run.sh` does the whole measurement: it builds the harness with `build.rs`'s flags against the vendored tree and against the same tree with every patch in `crates/sameboy-sys/patches/` reverse-applied (`patch -R`, no clone), then runs simultaneous pairs. The patch's text changed in this leaf (named tags, upstream's comment line restored) but its code did not, so the figure measures the same machine code. Two runs of `scripts/bench/layer-patch-cost/run.sh tests/corpus/fetched/blargg/cpu_instrs/cpu_instrs.gb` (8 pairs of 7,200 frames each; Apple M1, Apple clang 21; load average 8–9): **median +1.00%** (range +0.71% to +1.70%) and **median +1.15%** (range +0.64% to +1.76%); every pair was positive. The earlier +0.44% was taken at load 23–42, where the spread swamped it. "One well-predicted branch" was also wrong: see [What the patch costs with no buffer](#gbclis-layer-identity-patch).

**On, through the backend.** After a 100-frame boot, `cargo run --release -p gbcli-sameboy --example bench -- tests/corpus/fetched/blargg/cpu_instrs/cpu_instrs.gb 3600 1 <mode>`, where `plain` leaves capture off and `layers` turns it on: best of eight interleaved runs each gave `plain` 23.7× and `layers` 22.7× realtime; five paired runs put the on cost at **median 3.1%** (range 1.2–6.8%). The on path writes one byte per drawn pixel (23,040 bytes a frame) and takes the branch instead of predicting it. These figures were taken under load 25–45 and are not comparable with the stage-1 `plain` 19.2× recorded at load 3–6.


## gbcli's mode-blocked-writes patch

`crates/sameboy-sys/patches/mode-blocked-writes.patch` (leaf si5fnG, 2026-11-09) lets gbcli count, exactly, the program's writes the PPU drops, for the run warning "N VRAM writes ignored in mode 3, first at …" and its OAM twin (design §11, the 2026-11-09 update). SameBoy decides a write is dropped in one place per kind and returns without a trace: `write_vram` returns when `vram_write_blocked` is set (mode 3), and `write_high_memory` returns for $FE00-$FEFF when `oam_write_blocked` is set (modes 2-3), after triggering the DMG OAM bug. Both have just synced the display (`GB_display_sync`), so the flag is exact even inside a mode 3 that `render_line` batches.

- **`Core/gb.h`**: a callback type, `gbcli_ignored_write_callback_t (gb, addr)`, and its pointer `ignored_write_callback` after `lcd_status_callback`, in the `unsaved` section: no save state changes (`the_log_leaves_the_state_as_it_was` in `crates/sameboy/tests/it/ignored_writes.rs` compares the states of the same run with the log on and off).
- **`Core/memory.c`**: one line in each blocked branch, `if (gb->ignored_write_callback) gb->ignored_write_callback(gb, addr);`, before the return (and before `GB_trigger_oam_bug`). With no callback the cost is a null test on a path that is already `unlikely`.
- **Not counted:** OAM DMA and HDMA (not CPU writes; HDMA writes VRAM even in mode 3), a CPU write that OAM DMA, not the mode, drops or redirects (`is_addr_in_dma_use` in `GB_write_memory`, and `GB_is_dma_active` after the blocked check), and $FEA0-$FEFF (blocked with OAM but holding none; the callback reports it and `crates/sameboy` filters it).
- **Shim and Rust:** `gbcli_set_ignored_write_callback` in `shim/gbcli_shim.c` sets the pointer. `crates/sameboy/src/ignored.rs` installs the callback for the instance's lifetime (as the LCD-status one), records a drop only while a run is in progress and the log is on (a `bus_write` by gbcli itself is not the program's), reads the line with `gbcli_ppu_line`, and the run loop stamps each step's drops with its PC, start and frame number, keeping per kind the count and the first. The core API is `Core::set_ignored_write_log` / `take_ignored_writes` (`gbcli_core::IgnoredWrites`, `Feature::IgnoredWriteLog`).

Rejected: the write-memory callback with a `GB_display_sync` of our own before the write, which needs no patch but would sync the display from outside SameBoy's own write path, on every VRAM and OAM write of every run, and checking `gbcli_ppu_mode` there, which is unknown (`-1`) exactly late in a batched mode 3. The patch is observation only and small enough to offer upstream.

## The core identity

Added by leaf `46uWtG` (2026-11-06), after the layer-identity patch shipped without changing anything that identified the state format.

- **What is recorded.** `sameboy_sys::CORE_VERSION` is `<SameBoy/COMMIT>+patches.<hash>`, where the hash (`sameboy_sys::PATCH_SET`, 16 hex digits) is computed by `build.rs` over every file in `crates/sameboy-sys/patches/`: each file's name, length and bytes in name order, FNV-1a 64-bit (it detects change; it doesn't need to resist forgery, so no hash crate). `build.rs` declares `rerun-if-changed=patches`, so adding, editing, renaming or removing a patch changes the identity on the next build with no number to bump by hand (checked by hand: touching a new file in `patches/` changed `gbcli version` from `ea667ad+patches.6a0e3ced` to `…47d95a0e`, and removing it changed it back). The hash code is one file, `crates/sameboy-sys/patch_set.rs`, shared by `build.rs` and `tests/patch_set.rs` through `#[path]`. The backend reports `CORE_VERSION` as `CoreInfo::version`, so it is what a checkpoint's `core.commit` field and `gbcli version` show.
- **What is refused.** The backend's state blob (`crates/sameboy/src/blob.rs`) is format 3, which records `PATCH_SET` after the version. A blob saved under another patch set is refused (`CoreError::InvalidState`, which the engine reports as `checkpoint_mismatch`/`CoreRejected` naming both identities), and so is a format-2 blob, the format of every state saved before the layer-identity patch; both reasons end with the remedy: load it with the gbcli build that saved it, or re-create the state from the ROM. A different SameBoy *commit* with the same patch set still loads with the engine's `OtherCommit` warning: upstream appends fields to the end of a section, which `read_section` zero-fills, whereas a patch of ours can change a layout anywhere, so a patch-set change is the one that must be refused.
- **The boot cache** (`.gbcli/cache/boot-<rom16>-<model>-<boot16>-<seed>-<core16>.gbck`) is keyed on the first 16 hex digits of the SHA-256 of the backend name and `CORE_VERSION`, so another build's entry is never even read; a stale one is rebuilt cold beside it.
- **Re-vendoring** moves both halves of the identity: `COMMIT` changes, and a patch rebased onto the new commit changes the hash.

> **Update, 2026-11-06 (leaf TCSC3C, after the independent re-review): the compiled tree is checked against the identity.** The identity hashes `patches/`, not what `build.rs` compiles, so an edit made directly in `SameBoy/Core/` without regenerating its patch would have changed the layout while keeping `PATCH_SET`, and older states would have loaded silently. The identity is still computed the same way (hashing the compiled tree instead would also refuse every state across a re-vendor, which the `OtherCommit` warning deliberately allows); instead a test proves the tree is upstream's plus exactly the patch set. `scripts/vendor-sameboy.sh` records **`SameBoy/CORE_SHA256`**, a hash of upstream's `Core/` taken before the patches are applied (`scripts/sameboy-core-hash.sh DIR`: the SHA-256 of `shasum -a 256` over every file, sorted by path). `the_vendored_core_is_upstream_plus_exactly_the_patch_set` in `crates/sameboy-sys/tests/patch_set.rs` copies `Core/`, reverse-applies every patch, last first (`patch -R -p5`), and requires the result to hash to that value; the failure names the remedy (put the edit in a patch, which changes the identity, or re-vendor). The recorded value was checked independently: `5e26f578…` is the hash of `Core/` in GitHub's tarball of `ea667ad79aa28409f034b1fd6da7304e1844750d` (`curl -sSL https://codeload.github.com/LIJI32/SameBoy/tar.gz/<commit>`, then `scripts/sameboy-core-hash.sh <extracted>/Core`), and appending a comment to `Core/timing.c` made the test fail. The test needs `patch` and `shasum` on `PATH` (both ship with macOS). The shim (`shim/`) is not part of the identity: it adds no state.

## How it is compiled

SameBoy's `make lib` is not used: on macOS its dylib exports no symbols and, without the `cppp` tool, its installed headers come out empty while make exits 0 (evaluation ▸ Build and linking). Instead `crates/sameboy-sys/build.rs` compiles `Core/*.c` with the `cc` crate:

- `-std=gnu11 -O2 -D_GNU_SOURCE -DGB_INTERNAL -DGB_VERSION="1.0.5" -DGB_COPYRIGHT_YEAR="2026"` — the evaluation's flags (since stage 1, `-O3 -DNDEBUG` instead of `-O2`; see the update below). `GB_VERSION` is read from `version.mk` and `GB_COPYRIGHT_YEAR` from `LICENSE`, as SameBoy's Makefile derives them, so they follow a re-vendor. `-O2` applies to debug builds too, since tests run the emulator for real.

  > **Update, 2026-11-06 (stage 1, leaf jQ3ATQ): now `-O3 -DNDEBUG`, plus our shim.** The evaluation's 21.8× baseline was SameBoy's own `make lib CONF=release`, which compiles with `-O3 -ffast-math -DNDEBUG -flto` (SameBoy Makefile:362–380 at `ea667ad`), not the `-O2` with asserts on that this build used. Linked against our `-O2` library, the unchanged `scripts/bench/sameboy-throughput/sb_bench.c` loop ran 17.7–18.2× (three runs; `cc -O2 -std=gnu11 -DGB_DISABLE_DEBUGGER -DGB_DISABLE_REWIND -DGB_DISABLE_CHEAT_SEARCH -Icrates/sameboy-sys/SameBoy sb_bench.c <target>/release/build/sameboy-sys-*/out/libsameboy.a -lm`, then `sb_bench cpu_instrs.gb 3600 1`); with `-O3 -DNDEBUG` it ran 20.7–21.7×. So `build.rs` now passes `-O3 -DNDEBUG`. Left out: `-ffast-math` (floating-point results would depend on the optimizer, a needless risk to determinism) and LTO (not available through a cc-built static library without cross-language LTO). `build.rs` also compiles `crates/sameboy-sys/shim/gbcli_shim.c` with the same flags: tiny C accessors over SameBoy internals (IME, halt, the bank mapped at an address, side-effect-free peeks, the pre-step illegal-opcode check, the layer buffer and the LCD-turn-on scrubbed-frame flag), so the struct layout is never mirrored in Rust.
- `-DGB_DISABLE_DEBUGGER -DGB_DISABLE_REWIND -DGB_DISABLE_CHEAT_SEARCH`, leaving out `debugger.c`, `sm83_disassembler.c`, `symbol_hash.c`, `rewind.c` and `cheat_search.c` (the files SameBoy's Makefile filters for the same switches). 16 of the 21 `Core/*.c` files are compiled. Why: see below.
- SameBoy's own warning set (Makefile `WARNINGS`: `-Wall` plus its `-Wno-…` exceptions, and `-Wno-extra` to cancel the `-Wextra` that cc adds) without `-Werror`, so a newer compiler's warning in vendored code can't break our build. At this commit the build is warning-free (Apple clang 21, observed with `cargo build` after `cargo clean -p sameboy-sys`).
- No SDL, no `cppp`, no RGBDS, no make. `cargo build` on a fresh copy of the tree with only `cargo`, `rustc`, `rustdoc` and `/usr/bin:/bin` on `PATH` succeeded, and `cargo test` passed there (2026-11-06).

FFI declarations are hand-written in `crates/sameboy-sys/src/lib.rs` (no bindgen), added as callers need them.

## Debugger and rewind: compiled out

**The suspected mismatch is real.** `Core/debugger.c` guards its rewind code with `#ifndef DISABLE_REWIND` (lines 2178, 2245, 2700), while the Makefile defines `GB_DISABLE_REWIND` and every other file tests that name. Compiling `debugger.c` with the build's define alone fails:

```
cc -std=gnu11 -O2 -D_GNU_SOURCE -DGB_INTERNAL -DGB_VERSION='"1.0.5"' -DGB_COPYRIGHT_YEAR='"2026"' \
   -Wno-multichar -DGB_DISABLE_REWIND -c Core/debugger.c
Core/debugger.c:2191:16: error: no member named 'rewind_sequences' in 'struct GB_gameboy_s'
Core/debugger.c:2209:9: error: call to undeclared function 'GB_rewind_pop'; …
(17 errors; exit 1)
```

It compiles with `-DGB_DISABLE_REWIND -DDISABLE_REWIND`, and with neither. So SameBoy's `make lib DISABLE_REWIND=1` (debugger on) does not build at this commit — an upstream bug worth reporting.

**Decision: compile out both the debugger and rewind**, which also sidesteps the bug, since `debugger.c` is not compiled.

- *Debugger.* We never drive SameBoy's text debugger (plan, fidelity rule 2); ours is built on the public hooks. Compiling it out enforces that rule in the build rather than by discipline, and removes the default input callbacks that read stdin (`gb.c:50-105`, only present with the debugger) — exactly what a headless server must never do. What we lose: `debugger_ticks` (we keep our own emulated-time counter anyway), `GB_cpu_disassemble` (text through the log callback, not the structured disassembly we want), SameBoy's symbol loading (we parse RGBDS `.sym` files ourselves), the `ld b, b` software breakpoint (ours comes from the execution hook), and cheat search (implied by `GB_DISABLE_DEBUGGER`). The memory read/write, execution and LCD callbacks the plan relies on are not behind the switch.
- *Rewind.* Our checkpoints are our own (envelope around `GB_save_state`); SameBoy's rewind buffer is unused, and it is inert unless `GB_set_rewind_length` is called. Compiling it out drops `rewind.c` and the per-frame push hook.
- *Kept:* cheats (`GB_DISABLE_CHEATS` not set; GameShark/Game Genie codes may be useful) and timekeeping (`GB_DISABLE_TIMEKEEPING` not set; headless runs use turbo with no cap, per the evaluation).

Both are one-line switches in `build.rs`: a two-way door. Turning the debugger back on with rewind still off needs `-DDISABLE_REWIND` as well.

## Boot ROMs

`scripts/build-roms.sh` builds SameBoy's open-source boot ROMs (Expat) from the vendored `.asm` with RGBDS (v1.0.4 here): it compiles `pb12.c`, converts the logo with `rgbgfx -Z -u -c embedded`, compresses it, then `rgbasm` + `rgblink -x` each of `dmg_boot mgb_boot cgb_boot cgb0_boot cgb_boot_fast agb_boot sgb_boot sgb2_boot`. The binaries and a copy of the license are committed in `crates/sameboy-sys/bootroms/`, and `sameboy_sys::boot_roms` embeds them, so a normal build needs no RGBDS. Rebuilding gives byte-identical output (checked with `shasum -c` across two runs). **Never commit Nintendo boot ROM dumps.**

SameBoy's DMG boot ROM hands over to the cartridge after 80–85 frames (the smoke ROM's first write appears between those frame counts; measured by bisecting the smoke test's frame budget, 2026-11-06).

The same script assembles gbcli's own test ROMs from `crates/sameboy-sys/tests/roms/*.asm` (today just `smoke.asm`) with `rgbasm`, `rgblink` and `rgbfix -v -p 0`. Since stage 1 it also assembles `crates/sameboy/tests/roms/*.asm` (the backend's test ROMs); a name ending in `_boot` (`quick_boot.asm`, a four-instruction boot ROM for fast tests) is linked unpadded with `rgblink -x` into a `.bin` instead.

## Headless smoke test

`crates/sameboy-sys/tests/smoke.rs` boots `smoke.gb` through the DMG boot ROM, runs the cartridge for 60 frames (counted in `GB_run` ticks, 140,448 per frame), and asserts that nothing reached file descriptor 1 (it redirects fd 1 to a file, so C `printf` output is caught, not just Rust's). The ROM writes once to echo RAM at `$F000`, which SameBoy logs; the test routes that line through its log callback and asserts it arrived. Without the log callback, the test fails with `SameBoy wrote to stdout: "Wrote 42 to f000 (RAM Mirror)\n"` (checked by deleting the `GB_set_log_callback` call). Note that SameBoy logs echo-RAM writes only in `$F000-$FDFF`; `$E000-$EFFF` goes through its plain RAM path silently.
