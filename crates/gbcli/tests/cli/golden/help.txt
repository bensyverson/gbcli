gbcli — a headless, deterministic Game Boy emulator for agents.

Each command opens a named session (.gbcli/sessions/NAME/), does one thing to
its machine, saves it and prints rows; --json prints the response line.

  act        run, step, checkpoint, restore, undo, power-cycle, write, poke,
             patch
             advance or change the machine; the stop becomes the head
  read       show, read, measure, equiv, shot, view, sym, checkpoints, sav,
             events
             look without changing the head
  configure  break, watch, delete
             change the session's settings
  project    gaps, sessions, sessions prune, sessions rm
             every session in .gbcli/, and what they share; no session needed
  build      new, build, song
             RGBDS from PATH: edit, build, restore, measure; song files
  server     serve, batch
             the JSON Lines protocol, for harnesses
  help       help, recipes, schema, doctor, opcode, version
             no session, ROM or network needed

First:  gbcli run game.gb --session demo --frames 120 --shot first.png
Then:   gbcli show --session demo    gbcli read pc frame --session demo
New:    gbcli doctor, then gbcli new game (a starter that builds and runs)
Learn:  gbcli help hardware (the DMG on one page), gbcli help traps,
        gbcli opcode 'jr nz, .loop' (bytes, cycles, flags)

Help:   gbcli VERB --help (one worked example each)
        gbcli recipes (goal → command)
        gbcli help TOPIC: addresses expressions time checkpointing writes
                          budgets exit-codes hardware traps optimize rgbds
                          music images flash
        gbcli schema (the JSON request grammar for serve and batch)
Exit:   0 ok, 1 no, 2 usage, 3 budget/conflict, 4 unreadable, 5 environment

gbcli run — advance the machine to a stop, then read and save

USAGE
  gbcli run [ROM] [--frames N | --until EXPR | --to ADDR] [--keys TOKENS] [--read EXPR]… [--shot PATH] [--audio-log] [--wav PATH] [--measure FROM..TO] [--profile] [flags]

The experiment verb. In this order, whatever the order of the flags: start
from --at, the head, or the boot handoff; apply --patch, --poke and --write in
the order given; schedule --keys; run until --until holds, --to is reached, a
breakpoint or watch fires, or the budget ends (--profile, --frame-budget and
--raster collect during the run); --measure on a copy of the stop; evaluate
--read; save --shot; save the audio (--audio-log, --wav, --piano,
--spectrogram); save --checkpoint. The stop becomes the session's new head. A
ROM argument is the same as --rom.

CLASS
  act: advances or changes the machine and saves the new head; needs a session (name one with a ROM to create it).

FLAGS
  --at NAME|~N            start from a named checkpoint or the head N changes back
  --from boot|power-on    start at the boot handoff when there is no head (default), or at power-on, which also skips the head; not with --at
  --since BASE            what frame and t count from: boot (default), power-on or a checkpoint name
  --until EXPR            stop when this condition holds
  --to ADDR               stop before the instruction at this address executes
  --frames N              frame budget; any run without a budget gets 600 frames, and using them all up without another stop is budget_exhausted
  --instructions N        instruction budget
  --ticks N               tick budget
  --write TARGET=BYTES…   bus write before the run, as the CPU would
  --poke TARGET=BYTES…    write backing memory before the run, no side effects
  --patch TARGET=BYTES…   patch the ROM before the run (recorded in checkpoints)
  --read EXPR…            evaluate at the stop; repeat for more
  --checkpoint NAME       save the stop state under this name
  --allow-uninit          read never-written bytes as their power-on values, with a warning
  --shot PATH             save a PNG of the screen at the stop (see the shot flags)
  --filmstrip PATH        save a PNG of the frames the run passed, in a row, each labeled (LCD-off frames kept); at most 16, more are counted and warned about
  --every N               with --filmstrip: keep a frame every N frames of the run (default 1)
  --audio-log             print every write the run made to the sound registers, decoded into notes and settings, at elapsed 2^23 Hz ticks since --since: the cheap sibling of --wav. Only this run's: writes made before the run (a sound engine's setup) aren't listed
  --wav PATH              save what the run played as a WAV (16-bit stereo, 32,768 Hz)
  --channels mixed|each   with --wav: each also saves every channel alone beside it (PATH's stem with -square1, -square2, -wave, -noise) by replaying the run muted
  --piano PATH            save a piano roll PNG of the notes the run's sound writes played
  --spectrogram PATH      save a spectrogram PNG of what the run played
  --measure FROM..TO      after the stop, on a copy of it: cycles from the first arrival at FROM to the next arrival at TO (one iteration; `gbcli measure` for more)
  --profile               cycles per routine over the run, by .sym, most exclusive cycles first
  --top N                 with --profile: only the N routines with the most exclusive cycles
  --frame-budget          each frame's active and idle (HALT) T-cycles over the run, and the lag frames: frames in which the CPU never halted
  --raster                each IO-register write the run made, by frame and line: register, value, writer's PC and ticks into the line (912 per line)
  --keys TOKENS           press and release buttons: 'A@0 -A@2 START@10' (frame offsets)
  --keys-file FILE        key tokens from a file, after --keys; # starts a comment

SHOT FLAGS (how the PNG is taken)
  --scale N               pixels per Game Boy pixel in the PNG, 1 to 16 (default 4); on run, also pixels per image pixel in --filmstrip, --piano and --spectrogram (default 1)
  --crop X,Y,W,H          only this rectangle of the 160x144 screen, in Game Boy pixels
  --live                  the pixels drawn so far this frame, not the last complete frame
  --any-frame             take the last frame even if it isn't a normal one (LCD off, blank)

SESSION FLAGS (every session verb)
  -s, --session NAME      the session to use (default: GBCLI_SESSION); naming a new one with a ROM creates it
  --rom FILE              the ROM a new session is created from; an existing session refuses another ROM
  --sym FILE              the .sym for a new session (default: the ROM's name with .sym, if it exists); an existing session refuses another
  --model MODEL           the model for a new session: dmg-b (default, also dmg), gbc (cgb-e, a GBC in CGB mode for a $80 or $C0 ROM), cgb0, …; an existing session refuses another
  --seed N                the RAM seed for a new session (default 0); an existing session refuses another
  --flash BOARD           a new session's cart is a flash-save board (`gbcli help flash` lists them; default: mask ROM); an existing session refuses another
  --allow-rom-change      load a stored state even though the ROM was rebuilt and the check refuses it

CHANGE FLAGS (every verb that changes the session)
  --rev sN                refuse the change if the session is no longer at this revision

OUTPUT FLAGS (every verb that sends a request)
  --json                  print the protocol's result object instead of rows
  --dir PATH              find .gbcli/ from PATH instead of the working directory (beats GBCLI_DIR)
  --as NAME               who is asking, for the event log (default: GBCLI_AS)

EXAMPLE
  gbcli run game.gb --session dx --until 'u16[wFrame] >= 60' --read wSpriteX
    creates session dx from game.gb, runs to the frame where wFrame reaches
    60, and prints the stop and wSpriteX

gbcli sessions rm — remove one session

USAGE
  gbcli sessions rm NAME [--with-checkpoints] [flags]

Remove a session and its history. A session with named checkpoints is refused
unless --with-checkpoints.

CLASS
  project: lists or removes the sessions in this project's .gbcli/, or reads what they share; takes no session.

FLAGS
  --with-checkpoints      remove the session even though it holds named checkpoints

OUTPUT FLAGS (every verb that sends a request)
  --json                  print the protocol's result object instead of rows
  --dir PATH              find .gbcli/ from PATH instead of the working directory (beats GBCLI_DIR)
  --as NAME               who is asking, for the event log (default: GBCLI_AS)

EXAMPLE
  gbcli sessions rm dx
    removes the session dx

gbcli watch — add a watchpoint on reads, writes or both

USAGE
  gbcli watch read|write|access ADDR [--if EXPR] [--once] [flags]

Stop every later run at an access to ADDR. In --if, `old` and `new` are the
byte before and after a write. --once deletes it after it fires.

CLASS
  configure: changes the session's settings, not the machine; needs a session.

FLAGS
  --if EXPR               stop only when this condition holds
  --once                  delete the watch after it fires once

SESSION FLAGS (every session verb)
  -s, --session NAME      the session to use (default: GBCLI_SESSION); naming a new one with a ROM creates it
  --rom FILE              the ROM a new session is created from; an existing session refuses another ROM
  --sym FILE              the .sym for a new session (default: the ROM's name with .sym, if it exists); an existing session refuses another
  --model MODEL           the model for a new session: dmg-b (default, also dmg), gbc (cgb-e, a GBC in CGB mode for a $80 or $C0 ROM), cgb0, …; an existing session refuses another
  --seed N                the RAM seed for a new session (default 0); an existing session refuses another
  --flash BOARD           a new session's cart is a flash-save board (`gbcli help flash` lists them; default: mask ROM); an existing session refuses another
  --allow-rom-change      load a stored state even though the ROM was rebuilt and the check refuses it

CHANGE FLAGS (every verb that changes the session)
  --rev sN                refuse the change if the session is no longer at this revision

OUTPUT FLAGS (every verb that sends a request)
  --json                  print the protocol's result object instead of rows
  --dir PATH              find .gbcli/ from PATH instead of the working directory (beats GBCLI_DIR)
  --as NAME               who is asking, for the event log (default: GBCLI_AS)

EXAMPLE
  gbcli watch write rDMA --session dx --once
    stops the next run when OAM DMA starts

Time — every frame and cycle count says what it counts from.

  boot        the default: the boot ROM's handoff to the cartridge (PC=$0100).
              Before it, counts come from power-on and say so.
  power-on    tick 0
  NAME        a named checkpoint

--since BASE changes the base for run and read; stop rows print since=.
The first run of a ROM runs the real boot ROM once and caches the handoff in
.gbcli/cache/; later runs start there. --from power-on starts cold instead.

RGBDS — the loop: edit, build, restore, measure, with RGBDS from PATH.

  gbcli doctor                 RGBDS at the pinned version? (exit 5 names the
                               install command)
  gbcli new game               a starter: header, VBlank handler, OAM DMA in
                               HRAM, hardware.inc, a sprite on screen
  gbcli build game             rgbasm every src/**/*.asm (include/ on the
                               path), rgblink to build/game.gb + .sym + .map,
                               rgbfix -v -p 0xFF. No build file: the layout
                               is the build; --src, --include, --out change it;
                               PNGs in assets/ too (gbcli help images)
  gbcli build game --gbc       the same, for the GBC in dual mode: rgbfix -c
                               sets $0143 = $80, so the ROM is GBC-enhanced
                               and still runs on the DMG. (Pan Docs calls
                               the GBC the CGB.) rgbfix -C (GBC only, $C0)
                               isn't offered. A session runs it on the DMG
                               unless made with --model gbc (a GBC in CGB
                               mode), so check a dual ROM in two sessions
  The loop, from inside game/:
    gbcli run build/game.gb --session game --frames 60 --checkpoint start
    (edit src/)
    gbcli build --session game --restore start
    gbcli measure VBlank..VBlank.done --session game

Each error is a `diagnostic` row with file= and line=; a message repeated on
lines in a row is one row with lines=FIRST-LAST and count=N. build_failed
exits 4 and leaves the last good ROM in place. --restore loads the checkpoint
into the rebuilt ROM only if nothing it was running moved; rom_changed (exit
3) lists what did, and --allow-rom-change loads it anyway.

gbcli build — assemble, link and fix a project with RGBDS; errors with file and line

USAGE
  gbcli build [DIR] [--src DIR]… [--include DIR]… [--out FILE] [--gbc] [--session NAME --restore NAME] [flags]

Builds the project in DIR (default: here) by convention: rgbasm assembles
every .asm under src/ with include/ on the include path, rgblink links them
into build/<DIR's name>.gb with a .sym and a .map, and rgbfix fixes the
header. Each step's outputs must exist and be non-empty. Every diagnostic is a
`diagnostic` row with its file and line (a message repeated on lines in a row
is one row, with lines= and count=); any error fails with build_failed (exit
4) and leaves the last good ROM in place. With --session and --restore, a good
build is reloaded: the checkpoint is restored into the rebuilt ROM, which
loads only if nothing it was running moved (rom_changed, exit 3, says what
did).

CLASS
  build: runs RGBDS from PATH, checked against the pinned version (`gbcli doctor`); a session only to reload the build into; `new` and `song` need neither.

FLAGS
  --src DIR…              assemble every .asm under DIR instead of src/ (relative to the project)
  --include DIR…          put DIR on rgbasm's include path instead of include/
  --out FILE              the ROM to write, with its .sym and .map beside it (default build/<project>.gb)
  --gbc                   build for the GBC in dual mode: rgbfix -c sets $0143 to $80, and the ROM still runs on the DMG
  --restore NAME          after a good build, restore this checkpoint into --session, under the rebuilt-ROM check

MORE FLAGS
  -s, --session NAME      the session to use (default: GBCLI_SESSION); naming a new one with a ROM creates it
  --allow-rom-change      load a stored state even though the ROM was rebuilt and the check refuses it

CHANGE FLAGS (every verb that changes the session)
  --rev sN                refuse the change if the session is no longer at this revision

OUTPUT FLAGS (every verb that sends a request)
  --json                  print the protocol's result object instead of rows
  --dir PATH              find .gbcli/ from PATH instead of the working directory (beats GBCLI_DIR)
  --as NAME               who is asking, for the event log (default: GBCLI_AS)

EXAMPLE
  gbcli build --session game --restore start
    rebuilds the project here, then restores checkpoint start of session game
    into the new ROM

gbcli version — gbcli's, the protocol's and the core's versions

USAGE
  gbcli version [--json]

Prints gbcli's version and the SameBoy commit and patch set it was built with,
the line `gbcli --version` prints. --json adds the protocol version:
result.version is {gbcli, protocol, sameboy, patch_set}, the `version` op's
answer, which a program driving `gbcli serve` reads by sending
{"op":"version"} (`gbcli schema`).

CLASS
  help: no preconditions: works with no session, no ROM and no network.

MORE FLAGS
  --json                  print the protocol's result object instead of rows

EXAMPLE
  gbcli version --json
    prints the versions, the protocol's among them, as the response line
