gbcli — a headless, deterministic Game Boy emulator for agents.

Each command opens a named session (.gbcli/sessions/NAME/), does one thing to
its machine, saves it and prints rows; --json prints the response line.

  act        run, step, checkpoint, restore, undo, power-cycle, write, poke,
             patch
             advance or change the machine; the stop becomes the head
  read       show, read, measure, equiv, shot, view, sym, checkpoints, sav,
             events
             look without changing the head
  configure  break, watch, delete
             change the session's settings
  project    gaps, sessions, sessions prune, sessions rm
             every session in .gbcli/, and what they share; no session needed
  build      new, build, assets, song
             RGBDS from PATH: edit, build, restore, measure; song files
  server     serve, batch
             the JSON Lines protocol, for harnesses
  help       help, recipes, schema, doctor, opcode, version
             no session, ROM or network needed

gbcli run — advance the machine to a stop, then read and save

USAGE
  gbcli run [ROM] [--frames N | --until EXPR | --to ADDR] [--keys TOKENS] [--read EXPR]… [--shot PATH] [--audio-log] [--wav PATH] [--measure FROM..TO] [--profile] [flags]

The experiment verb. In this order, whatever the order of the flags: start
from --at, the head, or the boot handoff; apply --patch, --poke and --write in
the order given; schedule --keys; run until --until holds, --to is reached, a
breakpoint or watch fires, or the budget ends (--profile, --frame-budget and
--raster collect during the run); --measure on a copy of the stop; evaluate
--read; save --shot; save the audio (--audio-log, --wav, --piano,
--spectrogram); save --checkpoint. The stop becomes the session's new head. A
ROM argument is the same as --rom.

CLASS
  act: advances or changes the machine and saves the new head; needs a session (name one with a ROM to create it).

FLAGS
  --at NAME|~N            start from a named checkpoint or the head N changes back
  --from boot|power-on    start at the boot handoff when there is no head (default), or at power-on, which also skips the head; not with --at
  --since BASE            what frame and t count from: boot (default), power-on or a checkpoint name
  --until EXPR            stop when this condition holds
  --to ADDR               stop before the instruction at this address executes
  --frames N              frame budget; any run without a budget gets 600 frames, and using them all up without another stop is budget_exhausted
  --instructions N        instruction budget
  --ticks N               tick budget
  --write TARGET=BYTES…   bus write before the run, as the CPU would
  --poke TARGET=BYTES…    write backing memory before the run, no side effects
  --patch TARGET=BYTES…   patch the ROM before the run (recorded in checkpoints)
  --read EXPR…            evaluate at the stop; repeat for more
  --checkpoint NAME       save the stop state under this name
  --allow-uninit          read never-written bytes as their power-on values, with a warning
  --shot PATH             save a PNG of the screen at the stop (see the shot flags)
  --filmstrip PATH        save a PNG of the frames the run passed, in a row, each labeled (LCD-off frames kept); at most 16, more are counted and warned about
  --every N               with --filmstrip: keep a frame every N frames of the run (default 1)
  --audio-log             print every write the run made to the sound registers, decoded into notes and settings, at elapsed 2^23 Hz ticks since --since: the cheap sibling of --wav. Only this run's: writes made before the run (a sound engine's setup) aren't listed
  --wav PATH              save what the run played as a WAV (16-bit stereo, 32,768 Hz)
  --channels mixed|each   with --wav: each also saves every channel alone beside it (PATH's stem with -square1, -square2, -wave, -noise) by replaying the run muted
  --piano PATH            save a piano roll PNG of the notes the run's sound writes played
  --spectrogram PATH      save a spectrogram PNG of what the run played
  --measure FROM..TO      after the stop, on a copy of it: cycles from the first arrival at FROM to the next arrival at TO (one iteration; `gbcli measure` for more)
  --profile               cycles per routine over the run, by .sym, most exclusive cycles first
  --top N                 with --profile: only the N routines with the most exclusive cycles
  --frame-budget          each frame's active and idle (HALT) T-cycles over the run, and the lag frames: frames in which the CPU never halted; the first row sums up the whole frames' active T-cycles (min, max, mean) and the busiest one, then a row per lag frame (--json has every frame)
  --raster                each IO-register write the run made, by frame and line: register, value, writer's PC and ticks into the line (912 per line)
  --keys TOKENS           press and release buttons: 'A@0 -A@2 START@10' (frame offsets)
  --keys-file FILE        key tokens from a file, after --keys; # starts a comment

SHOT FLAGS (how the PNG is taken)
  --scale N               pixels per Game Boy pixel in the PNG, 1 to 16 (default 4); on run, also pixels per image pixel in --filmstrip, --piano and --spectrogram (default 2 for --piano, 1 for the others: try --scale 4 for a short clip's spectrogram)
  --crop X,Y,W,H          only this rectangle of the 160x144 screen, in Game Boy pixels
  --live                  the pixels drawn so far this frame, not the last complete frame
  --any-frame             take the last frame even if it isn't a normal one (LCD off, blank)

SESSION FLAGS (every session verb)
  -s, --session NAME      the session to use (default: GBCLI_SESSION); naming a new one with a ROM creates it
  --rom FILE              the ROM a new session is created from; an existing session refuses another ROM
  --sym FILE              the .sym for a new session (default: the ROM's name with .sym, if it exists); an existing session refuses another
  --model MODEL           the model for a new session: dmg-b (default, also dmg), gbc (cgb-e, a GBC in CGB mode for a $80 or $C0 ROM), cgb0, …; an existing session refuses another
  --seed N                the RAM seed for a new session (default 0); an existing session refuses another
  --flash BOARD           a new session's cart is a flash-save board (`gbcli help flash` lists them; default: mask ROM); an existing session refuses another
  --allow-rom-change      load a stored state even though the ROM was rebuilt and the check refuses it

CHANGE FLAGS (every verb that changes the session)
  --rev sN                refuse the change if the session is no longer at this revision

OUTPUT FLAGS (every verb that sends a request)
  --json                  print the protocol's result object instead of rows
  --dir PATH              find .gbcli/ from PATH instead of the working directory (beats GBCLI_DIR)
  --as NAME               who is asking, for the event log (default: GBCLI_AS)

EXAMPLE
  gbcli run game.gb --session dx --until 'u16[wFrame] >= 60' --read '[wSpriteX]'
    creates session dx from game.gb, runs to the frame where wFrame reaches
    60, and prints the stop and the byte in wSpriteX

RGBDS — the loop: edit, build, restore, measure, with RGBDS from PATH.

  gbcli doctor                 RGBDS at the pinned version? (exit 5 names the
                               install command)
  gbcli new game               a starter: header, VBlank handler, OAM DMA in
                               HRAM, hardware.inc, a sprite on screen
  gbcli build game             rgbasm every src/**/*.asm (include/ on the
                               path), rgblink to build/game.gb + .sym + .map,
                               rgbfix -v -p 0xFF. No build file: the layout
                               is the build; --src, --include, --out change it;
                               PNGs in assets/ too (gbcli help images)
  gbcli build game --gbc       the same, for the GBC in dual mode: rgbfix -c
                               sets $0143 = $80, so the ROM is GBC-enhanced
                               and still runs on the DMG. (Pan Docs calls
                               the GBC the CGB.) rgbfix -C (GBC only, $C0)
                               isn't offered. A session runs it on the DMG
                               unless made with --model gbc (a GBC in CGB
                               mode), so check a dual ROM in two sessions
  gbcli assets game --json     the images alone, converted as build would,
                               with rgbgfx alone and nothing written: tile
                               maps and palettes; --manifest FILE instead
                               of a project (gbcli help images)
  The loop, from inside game/:
    gbcli run build/game.gb --session game --frames 60 --checkpoint start
    (edit src/)
    gbcli build --session game --restore start
    gbcli measure VBlank..VBlank.done --session game

Each error is a `diagnostic` row with file= and line=; the same message on the
same or the next line, back to back, is one row with lines=FIRST-LAST and
count=N, even when that is two typos; errors= counts rows. build_failed
exits 4 and leaves the last good ROM in place. --restore loads the checkpoint
into the rebuilt ROM only if nothing it was running moved; rom_changed (exit
3) lists what did, and --allow-rom-change loads it anyway.

Images — PNGs under assets/, converted by `gbcli build` with rgbgfx (RGBDS).

  assets/bg/town.png           a background: unique tiles + a tilemap
  assets/sprites/hero.png      8x16 objects; the whole sheet is one frame
  assets/sprites/hero.16x16.png  frames of 16x16, left to right, then down
  assets/tiles/font.png        a tileset: a background's unique tiles, no
                               map (build your own from --json's tile_map)
Draw each image in up to 4 colors (sprites: 3 + transparent, alpha 0).
Shades 0-3 (white to black) are chosen once for the whole project, so a
color is one shade in every image, by the first rule that applies:
  1. declared   the dmg line of assets/palettes.txt (below): the colors of
                shades 0-3; each color takes its nearest entry's shade
  2. known      every color is in one palette: the DMG grays (#ffffff
                #aaaaaa #555555 #000000), the DMG-01 pea greens (#9bbc0f
                #8bac0f #306230 #0f380f), GB Studio's greens (#e0f8cf
                #86c06c #306850 #071821) or the Pocket grays as SameBoy draws
                them (#c2ce93 #818d66 #3a4c3a #07100e)
  3. stretched  lightness rescaled so the project's lightest color is shade
                0 and its darkest shade 3, then the nearest shade (nearest:
                one lightness only, so nothing to stretch)
The images row says which: shades=declared|known|stretched|nearest, and
palette= for a known one. Colors in one shade draw alike, with a
shared_shade warning: one per image for colors that image holds together,
and one for the project (no image=) for colors that share it only across
images: colors one image holds, or chained through one, are a group (a/b);
it lists each group with its images, and count= is the groups. Colors
equal in RGB555 (5 bits a channel, as rgbgfx reads them) are one color.
gbcli keys no color out: GB Studio's transparent green (#65ff00) is a
color here; make those pixels alpha 0.

assets/palettes.txt names palettes, one a line, 4 colors, index 0 (the
DMG's lightest) first, and assigns them to images by path under assets/:
  dmg:    #e0f8d0 #88c070 #346856 #081820   # reserved: the shades above
  forest: #fff #8c4 #363 #021               # #rgb is #rrggbb (#88cc44)
  ember:  #ffe #f80 #a20 #200
  bg/town.png = forest
Colors are #rrggbb or #rgb, kept as RGB555. Names are a lowercase letter,
then lowercase letters, digits or _. '#' then a space or tab (or '#' last
on a line) starts a comment; any other '#' word is a color, so a fifth
color is an error. A build uses the dmg line, checks the rest, emits every
palette as data, and builds an assigned image as DMG art; build --gbc
colors it too (GBC, below).

Every hardware limit is a `problem` row: limit, count, max, tiles=x,y (in
the image's 8x8 grid; --json lists them all), message and remedy.
  bg_tiles_map        256 unique tiles per background map
  vram_tiles          384 tiles shared by a background and all sheets
  obj_tiles           256 tiles for objects
  dmg_palette         4 shades for the background; 3 + transparent per sheet
  size_multiple_8     width and height a multiple of 8
  obj_pair_8x16       sheet and frame heights a multiple of 16
  obj_per_line        10 objects side by side in a frame
  obj_total           40 objects in a frame
  frame_grid          a sheet's width and height whole frames
  frame_span          a frame at most 256 pixels each way (OAM's bytes)
  romx_bank           one image's data and frame lists in a 16 KiB bank
  obj_no_transparency a warning: no transparent pixel, every object a block
                      (its remedy names #65ff00 when the sheet holds it)
  shared_shade        a warning: colors drawn in one shade (names them), in
                      one image or across images
  palette_file        assets/palettes.txt doesn't read: a bad line, a name
                      defined or an image assigned twice, two names with
                      one label (forest2, forest_2), an unknown name or
                      image, or dmg assigned (line=N)
  shade_stretched     a warning: the stretch put a color 2+ shades from its
                      nearest (e.g. #101010 beside only black, drawn white)
  alpha               a pixel half transparent, or any in a background
  gbc_palettes        build --gbc: over 8 palettes (names the tiles past 8)
  gbc_tile_colors     build --gbc: over 4 colors in a tile, or over 3
                      opaque colors in an object
  dmg_override_size   build --gbc: town.dmg.png isn't town.png's size
  shades_unpinned     build --gbc, a warning once for the project: indexed
                      art and no dmg line, so other art can recolor it
  rgbgfx_agrees       not a limit: rgbgfx drew other indices than gbcli
                      planned (a gbcli bug; re-save the PNG as 8-bit)

What the program gets (build/images/, rewritten by every build):
  INCLUDE "images.inc"   constants: TOWN_WIDTH, TOWN_HEIGHT (tiles),
                         TOWN_TILES, TOWN_BGP; HERO_TILES, HERO_FRAMES,
                         HERO_FRAME_WIDTH/HEIGHT, HERO_OBP; FONT_TILES
  labels                 TownTiles..TownTilesEnd (2bpp), TownTilemap..
                         TownTilemapEnd; HeroTiles..HeroTilesEnd (32 bytes
                         an object), HeroFrames: dw per frame -> count, then
                         y, x, tile, attributes per object ($20 X, $40 Y flip);
                         FontTiles..FontTilesEnd
  named palettes         PaletteForest..PaletteForestEnd (RGB555 dw, 8 bytes),
                         PALETTE_FOREST (its place in assets/palettes.txt)
  town.preview.png       the converted data as the DMG shows it, then its
                         unique tiles by use, most used first
Tile numbers count from the image's own first tile: TownTilemap's bytes,
HeroFrames' tile bytes and --json's tile_map all start at 0. Copy
TownTiles to tile N and add N to each map byte (and object tile) you
write. Tiles you load by hand go after TOWN_TILES, or the map is offset.

  gbcli build game, then gbcli run game/build/game.gb --frames 60 --shot a.png

GBC — gbcli build --gbc makes a ROM in dual mode (rgbfix -c, $0143 = $80):
GBC colors on a GBC, the same game in 4 shades on a DMG. Each image is
one of two kinds of art:
  color art     no palette assigned: drawn in any colors. gbcli packs its
                GBC palettes and derives its DMG version, each color
                taking its shade by the rules above. Its GBC tiles are
                their own data, behind the same map and frame lists.
                shared_shade then warns only for two colors in one tile
                (a sheet: one 8x16 object) that fall to one shade; a
                derived sheet in all 4 shades is dmg_palette.
  indexed art   assigned a palette in assets/palettes.txt: drawn in 4
                shades as DMG art; one set of tiles serves both machines,
                colored on the GBC by its palette, which the program can
                swap. A background's (or tileset's) index i draws entry
                i. A sheet's OBJ palette is its palette reordered by its
                OBP (sheets of one palette in different shades take one
                OBJ palette each). Without a dmg line its shades come
                from every color in the project, so adding or changing
                other art can move them: a sheet's OBP and so its OBJ
                palette, a background's index and so the entry it draws.
                shades_unpinned warns; a dmg line pins the shades.
To draw a color image's DMG version yourself, put town.dmg.png beside
town.png (hero.16x16.dmg.png beside hero.16x16.png): the same size, drawn
as DMG art, its colors shaded with the project's. A .dmg.png is an error
without --gbc, and beside indexed art, whose shades already are its DMG
version.
Limits: 8 BG palettes per background (one resident at a time), 4 colors a
tile; 8 OBJ palettes for all sheets together (indexed ones first), 3 +
transparent an object. Palettes the program only swaps in aren't counted.
Every tile is in VRAM bank 0 and no background tile is flipped, since the
DMG's tilemap has no flip bits; a sheet's objects still flip on both.

What a --gbc build adds:
  GBCLI_GBC              defined by the build in every source, images or
                         not (rgbasm -D GBCLI_GBC=1), not by images.inc:
                         IF DEF(GBCLI_GBC) keeps color code out of a DMG
                         build. The same ROM runs on both, so also test at
                         run time: the starter's hGbc (A = BOOTUP_A_CGB at
                         boot, and the header's $80)
  TownTilesGbc..End      color art's GBC tiles, same count and order as
                         TownTiles (indexed art uses TownTiles); HeroTilesGbc
                         likewise, color art only
  TownAttrmap..End       a byte per map entry, its BG palette in bits 0-2;
                         write it with VBK=1 where the tilemap goes
  TownPalettes..End      RGB555 dw, 8 bytes a palette, BG palette 0 first;
                         TOWN_PALETTES of them (indexed: its one palette)
  FontAttrs..End         a tileset's: a byte per tile, its BG palette, for
                         each map entry that uses it; FontPalettes,
                         FONT_PALETTES
  ObjPalettesGbc..End    every sheet's OBJ palettes, OBJ_PALETTES of them;
                         HeroFrames' attribute bits 0-2 pick one
  HeroPaletteIce..End    an indexed sheet's copy of each named palette,
                         reordered by HERO_OBP: what a swap loads into its
                         slot (RGB555 dw, 8 bytes)
  town.gbc.preview.png   the data in GBC colors, as screenshots show them,
                         then its palettes
On a GBC, with the LCD off: palettes through rBCPS/rBCPD (BG) and
rOCPS/rOCPD (OBJ), the attribute map with VBK=1, then VBK=0 and the GBC
tiles. A DMG has no VBK, so it must skip all of it, or the attribute map
lands on the tilemap.

Swap a palette (a GBC, in VBlank or with the LCD off; palette RAM is shut
while a line draws). Town, assigned forest, is BG palette 0; PaletteEmber
there recolors it, its tiles and map untouched (palette n: | n * 8):
    ld a, BGPI_AUTOINC          ; BG palette 0, color 0, then the next
    ldh [rBCPS], a
    ld hl, PaletteEmber
    ld b, PaletteEmberEnd - PaletteEmber
.swap
    ld a, [hli]
    ldh [rBCPD], a
    dec b
    jr nz, .swap
A sheet's is the same through OBPI_AUTOINC, rOCPS and rOCPD, from the
sheet's own copy: an indexed sheet's tiles hold OBP's indices, not
shades, so its slot holds its palette reordered by HERO_OBP, and so does
HeroPaletteIce (ice for hero), which loads where PaletteIce would draw
the wrong shades. Its slot is in HeroFrames' attribute bits 0-2.
https://gbdev.io/pandocs/Palettes.html#lcd-color-palettes-cgb-only
https://gbdev.io/pandocs/Tile_Maps.html#bg-map-attributes-cgb-mode-only

Compare d.png with the .preview.png files, g.png with the .gbc.preview.png.

gbcli build — assemble, link and fix a project with RGBDS; errors with file and line

USAGE
  gbcli build [DIR] [--src DIR]… [--include DIR]… [--out FILE] [--gbc] [--session NAME --restore NAME] [flags]

Builds the project in DIR (default: here) by convention: rgbasm assembles
every .asm under src/ with include/ on the include path, rgblink links them
into build/<DIR's name>.gb with a .sym and a .map, and rgbfix fixes the
header. Each step's outputs must exist and be non-empty. Every diagnostic is a
`diagnostic` row with its file and line (a message repeated on lines in a row
is one row, with lines= and count=); any error fails with build_failed (exit
4) and leaves the last good ROM in place. With --session and --restore, a good
build is reloaded: the checkpoint is restored into the rebuilt ROM, which
loads only if nothing it was running moved (rom_changed, exit 3, says what
did).

  --include DIR…          put DIR on rgbasm's include path instead of include/
  --out FILE              the ROM to write, with its .sym and .map beside it (default build/<project>.gb)
  --gbc                   build for the GBC in dual mode: rgbfix -c sets $0143 to $80, and the ROM still runs on the DMG
  --restore NAME          after a good build, restore this checkpoint into --session, under the rebuilt-ROM check

MORE FLAGS
  -s, --session NAME      the session to use (default: GBCLI_SESSION); naming a new one with a ROM creates it
  --allow-rom-change      load a stored state even though the ROM was rebuilt and the check refuses it

gbcli assets — convert a project's or a manifest's images without building: tile maps, palettes

USAGE
  gbcli assets [DIR] [--manifest FILE] [--gbc] [--keep DIR] [--json]

Converts the PNGs under DIR's assets/ (default: here), or the images a
manifest names, exactly as `gbcli build` would, with rgbgfx alone: no rgbasm,
no rgblink, no session. Prints the `image`, `problem` and `images` rows a
build prints; --json gives each image's tile_map (tile, flip and GBC palette
per source tile) and palettes. Nothing is written unless --keep names a
directory; images.asm and images.inc are a build's. A problem fails with
build_failed (exit 4), its rows printed. A manifest names each image as its
path under assets/ in a project (`tiles/font.png`), the file to read, and the
palettes palettes.txt would hold.

CLASS

gbcli version — gbcli's, the protocol's and the core's versions

USAGE
  gbcli version [--json]

Prints gbcli's version and the SameBoy commit and patch set it was built with,
the line `gbcli --version` prints. --json adds the protocol version:
result.version is {gbcli, protocol, sameboy, patch_set}, the `version` op's
answer, which a program driving `gbcli serve` reads by sending
{"op":"version"} (`gbcli schema`).

CLASS
  help: no preconditions: works with no session, no ROM and no network.

MORE FLAGS
  --json                  print the protocol's result object instead of rows

EXAMPLE
  gbcli version --json
    prints the versions, the protocol's among them, as the response line
